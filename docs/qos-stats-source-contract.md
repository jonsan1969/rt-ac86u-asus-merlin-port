# QoS Stats source integration contract

Date: 2026-09-28  
Feature inventory ID: M46  
Related feature: M64 Traditional QoS overhead/download statistics  
Runtime baseline: ASUS RT-AC86U 3.0.0.4.386_52334  
Merlin donor: 386.14_2 @ `6a5df61aab6f3fa2dffc518994d42e4f2a27fb2b`

## Purpose

Restore the Merlin **QoS Classification / QoS Stats** page without replacing ASUS 52334 QoS, TrendMicro/BWDPI, `tc`, HTTPD or kernel components.

M46 has two read-only backend surfaces:

1. traffic-control class statistics;
2. BWDPI classified connection statistics.

M64's download-side statistics requirement is owned by the first M46 backend. Do not implement a second tc-statistics path for M64.

## Donor WebUI/data flow

Pinned Merlin page:

`/www/QoS_Stats.asp`

polls:

`/ajax_gettcdata.asp`

The AJAX endpoint contains:

```
<% get_tcclass_array(); %>;
<% bwdpi_conntrack(); %>;
```

The HTTPD handlers live in donor `httpd/data_arrays.c`.

The page reads:

- `tcdata_lan_array` for download/LAN-side class stats;
- `tcdata_wan_array` for upload/WAN-side class stats;
- `bwdpi_conntrack` for classified active flows;
- IPv6 client/name data from the existing client-array API.

## Part A — traffic-control class statistics

Pinned donor `ej_tcclass_dump_array()`:

- returns empty valid arrays when QoS is disabled;
- reads current `qos_type`;
- for Traditional/Adaptive/GeForce-style classful modes, gathers LAN/download class data;
- gathers WAN/upload class data for non-BW-Limiter modes;
- parses `tc -s class` output into:
  - class id;
  - cumulative bytes;
  - current bit rate;
  - current packet rate.

### Donor interfaces

Pinned donor invokes:

- `tc -s class show dev br0`;
- `tc -s class show dev imq0`;
- `tc -s class show dev <wan_ifname>`.

This interface layout must **not** be assumed for ASUS 52334 HND.

The final port must identify the actual 52334 QoS classful interfaces from the later ASUS QoS generator/runtime and query those interfaces only.

### Parser contract

For Traditional/GeForce donor modes, the parser recognizes HTB class IDs across the donor's class hierarchy.

For Adaptive mode it expects `class htb 1:<id>`.

It skips root/system classes and emits rows:

```
["class-id","bytes","rate-bps","rate-pps"]
```

The final parser must be matched to the actual qdisc/class layout generated by ASUS 52334.

Do not display misleading class labels when the target uses a different class hierarchy.

## Safer tc collection

Pinned donor shells out through `system()` and a shared `/tmp/tcclass.txt`.

The new implementation should avoid that pattern where practical.

Preferred order:

1. use netlink/rtnetlink APIs if already available in the ASUS source tree;
2. otherwise fork/exec `tc` with fixed argv and capture output through a pipe;
3. only as a last resort use a uniquely named locked temporary file.

Requirements:

- no shell interpolation of interface names;
- interface names validated against active ASUS-owned interfaces;
- no shared predictable temp-file race;
- bounded output and parse time;
- read-only operation.

## Part B — BWDPI classified connections

Pinned donor `ej_bwdpi_conntrack()` is compiled under `RTCONFIG_BWDPI`.

It requires the TrendMicro application database and reads classified flow data from:

`/proc/bw_cte_dump`.

For each flow it parses:

- IP version;
- protocol;
- source IP/port;
- destination IP/port;
- classification mark.

The mark is split into AppID and category, then mapped to a description through the app database.

The emitted JS rows contain:

`[protocol, src_ip, src_port, dst_ip, dst_port, description, category, appid]`.

### IPv6 handling

Pinned TrendMicro flow output uses a nonstandard IPv6 text form in this donor generation.

The donor applies `_fix_TM_ipv6()` before returning IPv6 addresses.

For ASUS 52334, first inspect the actual `/proc/bw_cte_dump` format.

Only apply the donor repair if the target still produces the same malformed/pair-delimited format.

Do not corrupt already valid IPv6 strings.

## BWDPI database caching

Pinned donor builds an in-process hash table keyed by `AppID-category` and invalidates it when the application database ctime changes.

The final implementation may reuse that pattern but must fix failure-path memory handling and make the cache safe for the actual HTTPD execution model.

Requirements:

- bounded database entry count;
- allocation failures return an empty dataset safely;
- database reload frees all cached state;
- no use-after-free across requests;
- malformed database rows are ignored.

## Feature degradation

The page must degrade cleanly.

### QoS disabled

Return valid empty tc arrays.

### Unsupported QoS mode / no classful qdisc

Hide class charts or show a clear "not available for this QoS mode" state.

### BWDPI unavailable/stopped

Return:

`bwdpi_conntrack=[]`

without failing the tc statistics.

### App database unavailable

Connection rows may be omitted or safely labeled untracked/unknown; do not crash HTTPD.

## UI adaptation

Once backend handlers exist, stage as add-only/exact page integration:

- `QoS_Stats.asp`;
- `ajax_gettcdata.asp`;
- required chart library only if not already supplied by the project;
- Adaptive QoS menu entry.

The project already includes a pinned local Chart.js for M49. Reuse a compatible local copy rather than duplicate or fetch a CDN dependency.

Preserve ASUS 52334's newer Adaptive QoS UI and TrendMicro controls. Do not replace `QoS_EZQoS.asp`.

## Relationship to M64

M64 shaping accuracy and M46 statistics are related but distinct.

- M64 source changes affect generated shaping parameters.
- M46 reads resulting qdisc/class state.
- M64 download-statistics requirement is satisfied by M46's LAN/download tc backend.

The same interface/class mapping should be used by validation for both features.

## Relationship to M48

M48 per-IP historical/live traffic monitoring uses cstats/ipt accounting and is a separate backend.

Do not make M46 depend on cstats.

BWDPI connection classification may exist even when M48 is not ported.

## Security/performance boundary

All handlers are read-only.

Polling must not:

- change QoS rules;
- restart TrendMicro;
- write NVRAM;
- create unbounded child processes;
- scan arbitrary user-supplied paths.

Default refresh cadence must not cause material CPU load on RT-AC86U.

## Validation gate

Before M46 becomes **SUCCESS**, prove:

1. QoS disabled returns valid empty tc arrays;
2. supported QoS mode reports correct upload classes;
3. supported QoS mode reports correct download classes;
4. byte counters match direct target-side tc/netlink observations;
5. rate values are parsed correctly;
6. target interface selection matches ASUS 52334 QoS runtime;
7. no stale temp file or concurrent-request race exists;
8. BWDPI unavailable returns an empty connection list safely;
9. BWDPI classified IPv4 flows show correct AppID/category/description;
10. IPv6 flows render valid addresses;
11. app database refresh/replacement invalidates cache safely;
12. unknown AppID/category does not crash the handler;
13. page refresh causes no QoS state changes;
14. polling remains responsive under a large connection table;
15. M64 uses this same download-statistics path;
16. ASUS QoS, TrendMicro and HTTPD core behavior remains authoritative.

## Current classification

**C backend + A UI after backend**

The feature needs narrow read-only HTTPD/data integration. It does not justify replacing ASUS QoS or HTTPD.
