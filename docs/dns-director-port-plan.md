# DNS Director compatibility port — ASUS 52334 backend

Date: 2026-09-24  
Feature inventory ID: M26  
Donor concept: Asuswrt-Merlin 386.14_2 DNS Director  
Runtime baseline: ASUS RT-AC86U 3.0.0.4.386_52334

## Finding

ASUS 52334 still contains a functional DNSFilter backend even though the WebUI is disabled/removed.

Verified in the stock 52334 image:

- `rc` contains `dnsfilter_enable_x`, `dnsfilter_mode`, `dnsfilter_rulelist` and `dnsfilter_custom1..3`;
- `rc` contains DNSFilter IPv4 and DNS-over-TLS enforcement chains;
- `httpd` retains the `dnsfilter_modes_list` EJS handler;
- `rc` retains the `dnsfilter` service name;
- the common service parser handles `restart_<service>` generically, so `restart_dnsfilter` maps to the retained `dnsfilter` service;
- stock language dictionaries and client-list JavaScript still contain DNSFilter support;
- stock `state.js` evaluates `isSupport("dnsfilter")` and then explicitly forces `dnsfilter_support = false`;
- the actual `DNSFilter.asp` page is absent from the stock rootfs.

The reason ASUS disabled the WebUI is not proven by the available artifacts. Therefore this port does not assume that Merlin's full implementation can simply be restored unchanged.

## Important backend difference

Merlin 386.14_2 extends HND DNS Director storage with:

- `dnsfilter_rulelist1` ... `dnsfilter_rulelist5`;
- `dnsfilter_custom61` ... `dnsfilter_custom63` for custom IPv6 resolvers.

Those signatures are absent from ASUS 52334.

The initial port therefore **does not use them**.

## Initial compatibility scope

The first adapter deliberately stays inside the verified ASUS 52334 contract:

- enable/disable: `dnsfilter_enable_x`;
- global mode: `dnsfilter_mode`;
- custom IPv4 resolvers: `dnsfilter_custom1..3`;
- one client rule field: `dnsfilter_rulelist`;
- mode list generated by stock `httpd` through `dnsfilter_modes_list()`;
- apply action: `restart_dnsfilter`.

Because the stock backend exposes only one rulelist field, the WebUI enforces a 255-byte serialized rule-list limit instead of silently overflowing into Merlin-only NVRAM variables.

Discontinued mode IDs 2, 3 and 4 are hidden by the adapter.

## Menu integration

The adapter is installed as `/www/DNSFilter.asp` because the ASUS 52334 WebUI still contains historical references to that URL.

Menu integration must be an exact, SHA-256-pinned patch against the verified 52334 `menuTree.js`. No whole-file replacement is allowed.

The patch must:

1. add a LAN tab for `DNSFilter.asp` / DNS Director;
2. prevent the router-mode exclusion list from hiding that URL;
3. leave AP/repeater/media-bridge exclusions intact.

## Deferred Merlin enhancements

The following remain **IN PROGRESS** and require source-level core work before they are enabled:

- extended HND client-list storage across rulelist1..5;
- custom IPv6 resolver fields;
- Merlin IPv6 DNS Director semantics where ASUS 52334 differs;
- any dnsmasq/firewall behavior absent from the ASUS backend.

## Safety rule

This feature may progress to runtime testing only if:

- the page is add-only;
- the menu edit matches the exact ASUS 52334 file hash and patch context;
- no `rc`, `httpd`, `dnsmasq` or kernel binary is replaced;
- all posted NVRAM names are verified stock 52334 names.
